# 0004 서비스는 실행 역할로만 붙고, 마이그레이션은 따로 돈다

## 맥락
서비스가 스키마 소유자 자격으로 붙으면, 뚫렸을 때 표를 지우거나 바꿀 수 있다. 서빙 중에 마이그레이션이 돌면 옛 판과 새 판이 같은 DB 를 함께 보는 동안 깨질 수 있다.

## 선택지
1. 서비스가 소유자 자격으로 붙고 기동 때 스스로 마이그레이션한다.
2. 소유자·마이그레이션·실행 역할을 나누고, 마이그레이션은 끝나면 멈추는 일회성 단계로 돌린다.

## 결정
2. 서빙은 실행 역할(`map_<서비스>_runtime`)만, 일회성 단계는 그 단계의 로그인만 받는다. 빈 볼륨에서는 compose 의 DB 준비 사슬이 역할·스키마·마이그레이션을 순서대로 만든다(`db/setup/`).

## 결과
- 빈 볼륨 첫 기동에 준비 단계 7개가 먼저 돈다. 두 번째 기동부터는 건너뛴다.
- 각 서비스는 섞인 자격을 받으면 기동을 거부하므로, 자격을 잘못 넘기면 그 자리에서 드러난다.
- 역할 SQL 은 서비스 저장소가 갖고, 이 저장소는 순서만 갖는다.
